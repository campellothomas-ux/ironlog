# Protéger les données locales avant restauration

Une sauvegarde malformée ou un échec de stockage pouvait laisser l'application annoncer un succès ou repartir silencieusement d'une base de démonstration. Cette PR vérifie la sauvegarde complète avant de présenter un aperçu, puis écrit l'état restauré avant de remplacer l'état mémoire. Une base locale illisible reste intacte et ouvre un écran de récupération.

Le format versionné conserve les états V4, leur clé locale, les programmes, performances, séance en cours, préférences et calendrier. Les écritures legacy échouées reviennent au dernier état enregistré avec un message ; la fin de séance existante est conservée. Les sauvegardes sont locales, sans synchronisation ni fusion automatique. Voir [DATA-SAFETY.md](DATA-SAFETY.md) pour le format, les limites et la migration.

Validation : `npm ci`, lint et build réussis ; 22 tests unitaires et intégration dans chacun des fuseaux Paris et New York ; 55 parcours Chromium réussis sur cinq formats, y compris stockage saturé ou inaccessible, annulation, restauration et base corrompue. Captures : [aperçu](captures/data-safety/backup-preview.png) et [récupération](captures/data-safety/recovery.png). Safari et PWA iPhone, Fichiers/iCloud Drive et les gros fichiers sur appareil réel nécessitent une vérification manuelle avant fusion. WebKit ne peut pas être installé si le proxy maintient le refus sur ses hôtes de téléchargement. Aucun déploiement manuel ni fusion.

Avant validation : exporter une copie externe de l'état actuel, vérifier le fichier dans Fichiers, puis importer sur une preview séparée. Tester également annulation, quota, récupération et rechargement sur iPhone. Les données de preview restent séparées du site principal.
